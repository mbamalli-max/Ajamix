3. **`lang` / `dir` attributes — the most important fix.** The page currently has no `lang="ha-Arab"`,
   no `lang="ar"`, and no `dir="rtl"` attributes on any specimen; it drives font selection purely through
   CSS classes (`.arabic-span`). That demonstrates two-font switching but does **not** exercise the
   language-driven selection the approved architecture actually specifies, so acceptance criterion #10
   cannot be validated against the real production mechanism.

   Rework specimen markup so font selection is genuinely **language-attribute driven**, matching the
   approved architecture:

   ```css
   .hausa-ajami,
   [lang="ha-Arab"] {
     font-family: "AJAMIX Harmattan", "AJAMIX Shipped Noto", serif;
     direction: rtl;
   }
   .arabic,
   [lang="ar"] {
     font-family: "AJAMIX Shipped Noto", "AJAMIX Harmattan", serif;
     direction: rtl;
   }
   ```

   Every Hausa Ajami specimen container must carry `lang="ha-Arab"` **and** `dir="rtl"` (do not rely on
   the language tag to set direction). Every Arabic/Qur'anic specimen must carry `lang="ar"` and
   `dir="rtl"`. Keep the existing three-way comparison (Harmattan / shipped Noto / system fallback) —
   it is correct and must not be lost.
