Objective:        Convert the 359 curriculum images from ~813MB of PNGs to WebP (~35MB), repoint

## Why

`app/images/**` was removed from git history earlier today because 813MB of PNGs made the repo
unpushable and would have exhausted GitHub's free LFS quota. The images are currently on disk but
untracked and therefore absent from any git-based deploy. Measured on real files from this corpus, WebP
at width 1024 / quality 82 yields **95–97% reduction** (1.73MB → 51KB; 3.21MB → 181KB; 0.73MB → 36KB),
which brings the whole set to roughly 35MB — small enough to track in git normally, and a large
real-world win for the target users (Hausa learners on constrained mobile data).

## Steps

### 1. Write a conversion script at `tools/image-pipeline/png-to-webp.mjs`

It must be **idempotent, guarded, and re-runnable**, matching the defensive style of the existing scripts
in this repo (see `tools/audio-pipeline/segment-formal-modules.mjs` for the house pattern):

- Read every `app/images/*.png`.
- Write `app/images/<same-basename>.webp` using:
  `sharp(src).resize({ width: 1024, withoutEnlargement: true }).webp({ quality: 82 })`
- **Do not delete the source PNGs.** They are the masters and stay on disk (they will be gitignored).
- Skip conversion when an up-to-date `.webp` already exists (compare mtimes) so re-runs are cheap no-ops.
- Print a per-file and total before/after size summary, and a final count.
- Fail loudly if any output file is zero-length or if any input fails to convert — do not silently skip.

### 2. Verify every converted image before touching content.json

For all 359: the `.webp` exists, is non-zero, is a valid WebP that `sharp` can read back, and its decoded
pixel dimensions are the expected resized values (width 1024, or the original width if it was already
≤1024, with aspect ratio preserved). Report the total size before and after. **If any file fails, STOP
and report — do not proceed to step 3 with a partial conversion.**

### 3. Repoint `content.json` — guarded, minimal, reversible

Write a separate guarded script `tools/image-pipeline/repoint-imagecards.mjs` that:

- Backs up the current `app/content.json` to
  `ai-system/projects/ajamix/tasks/2026-07-28-pre-webp-content-389.json` **before** writing anything.
  (This path is outside `--repo`; it is covered by `--add-dir`, so the write will succeed.)
- For every module whose `imageCard` matches exactly `images/<id>.png`, rewrites it to `images/<id>.webp`.
- Asserts, before writing, that the corresponding `.webp` file actually exists on disk for every path it
  is about to rewrite. Any missing file = abort with no write.
- Changes **nothing else** — no other field, no key order, no formatting. After writing, re-parse the file
  and assert that it is deep-equal to the pre-write object except for exactly the `imageCard` string values
  that were intended to change, and that the module count is still 389.
- Is idempotent: a second run must be a clean no-op.
- Also handle `activities[].imageCard` if any activity references a `.png` under `images/` — check whether
  any do, and report either way. Apply the same rules if so.

### 4. Update `.gitignore`

Replace the bare `app/images/` line so that PNG masters stay out of git but WebP files are tracked:

```
app/images/*.png
```

(i.e. remove the directory-wide ignore, ignore only the PNGs.) Verify with `git status --short` that the
359 `.webp` files now appear as untracked/addable and **zero** `.png` files do.

### 5. Verify the app

- `node --test tools/audio-pipeline/qa-delivered-audio.test.mjs` passes.

  an export/share manifest). Report what you found. **Do not change `app/app.js` or `app/sw.js` without
  reporting first** — if a real code change is genuinely required, describe it and STOP rather than
  applying it, unless it is a trivial extension-agnostic fix, in which case apply it and flag it clearly.
